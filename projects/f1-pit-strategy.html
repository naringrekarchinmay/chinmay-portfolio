F1 Pit Strategy ML: 2025 Season

Can we predict whether a driver will pit in the next 3 laps, using only what's known up to the current lap? This pipeline tests that question against every race in the 2025 F1 season using FastF1 data.

GitHub Repo

Pit strategy is one of the biggest levers a team controls during a race, and timing is most of it. When a driver comes in depends on tyre degradation, stint length, track position, and whether a safety car or VSC window just opened up. This project started small, as a Monaco 2025 lap-time case study, and grew from there into a pipeline that can run on any track: can a model predict, using only what's known up to the current lap, whether a driver is about to pit in the next three laps?

It now runs across all 24 races of the 2025 season, roughly 26,700 laps, 21 drivers, and 10 teams. The pipeline standardizes lap data into one schema, builds leakage-safe features only (race progress, stint, tyre life, pit history that only looks backward, track status), and trains classification models. Validation is race-aware: it uses GroupShuffleSplit to hold entire races out of training instead of just shuffling rows, since shuffling would let the model peek at laps from the same race it's being tested on.

The dashboard has five pages: project overview, track explorer, strategy comparison, model predictions, and explainability, all wrapped in a dark liquid-glass theme. The original Monaco lap-time notebooks and model are still there too, sitting alongside the newer full-season pipeline.

Approach

How it was built.

01

Data collection

Pull lap timing, tyre/stint, pit, track-status, and weather data for every 2025 race via FastF1, resolved to an exact calendar round.

02

Standardization

Combine per-race laps into a single 29-column schema, then build the combined all-tracks dataset (24 races, ~26,700 laps).

03

Feature engineering

Build only leakage-safe features: race progress, position, tyre/stint, pit history that only looks backward, and track-status flags.

04

Race-aware modeling

Train Logistic Regression, Random Forest, and Gradient Boosting on will_pit_next_3_laps, validated with GroupShuffleSplit so entire races are held out.

05

Analysis & explainability

Compare pit-stop counts and stint lengths across tracks, then rank features by permutation importance and SHAP.

06

Dashboard

Serve everything through a five-page Streamlit dashboard with a dark liquid-glass theme that degrades gracefully if an artifact is missing.

One caveat worth stating plainly: the pit-stop target is imbalanced, only about 8.5% of laps are positive, so the tree models' high accuracy mostly just reflects the majority class. F1 and recall tell the truer story. These are modest baselines validated on races the models never saw during training, and the problem is far from solved.
